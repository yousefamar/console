# Context cost — findings (2026-09-08, ^brisk-wolf)

Moved out of CLAUDE.md by the diet (^rosy-owl). The one-paragraph rule lives in CLAUDE.md → Agents; this is the full write-up.

**Context cost — the CLI's tool-result clearing does NOT exist for hub sessions (^brisk-wolf, 2026-09-08; CLI 2.1.263).** Investigated because ~46 % of spend is re-reading the cached prefix. The CLI's "microcompact" (`W9n`: clear every Bash/Read/Grep/… tool_result except the last 5, ≥20k tokens saved, replaced by `[Old tool result content cleared]`) is the **`context_hint` beta** (`context-hint-2026-04-09`): the CLI sends `context_hint:{enabled}` only when `querySource.startsWith("repl_main_thread")` AND `includeFirstPartyBetas` — the SERVER rejects an overlong prompt with a hint, the CLI clears and retries (`retry:context-hint`). Hub sessions are `headless`/`headless_stream`/`sdk` on Bedrock, so it is doubly inert (zero clearing markers in 655 fleet transcripts), it is server-triggered overflow avoidance not a cost knob, and no env/setting enables it. The CLI never sends API `context_management` edits either (it only reads the field). The compaction env vars are different levers: `CLAUDE_CODE_AUTO_COMPACT_WINDOW` = the autocompact window (context-for-cost trade, Yousef's decision), `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` lowers the threshold, `CLAUDE_CODE_COLD_COMPACT` = `stripNonEssential` in the compaction summary, `CLAUDE_CODE_DISABLE_PRECOMPACT_SKIP` = load pre-compact transcript entries on resume, `DISABLE_AUTO_COMPACT`/`DISABLE_COMPACT`. **Measured instead (`scripts/context-clearing-sim.py`, compaction-aware — the odd-toad attribution's 24 % Bash figure ignored the 261 compactions; it is 13.8 % of cache_read):** clearing stale Bash results only at cold points (hibernation wake / first request, where the prefix is rebuilt anyway) would save 10.6 % of cache_read ≈ $430/wk and needs a hub-side transcript rewrite before `--resume` (the CLI's `hint_clears` record is in-memory only); ticket-forks are 65 % of cache_read and the parent transcript they inherit via `--fork-session` (~104k tokens at first request × ~490 requests each) is ~24 % of all cache_read ≈ $970/wk; average context per request is ~340k tokens for forks and roots alike. Any of those is a design decision, not a config flip — Yousef approved the first (compact-at-fork-spawn, shipped, see the Dispatch bullet in Boards); wake-time Bash clearing and per-fork `CLAUDE_CODE_AUTO_COMPACT_WINDOW` remain unbuilt options. Re-run the sim after a week to measure the real effect.
