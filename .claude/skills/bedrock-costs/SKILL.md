# Bedrock spend analytics

Moved out of `CLAUDE.md` on 2026-09-08 (the CLAUDE.md diet, ^rosy-owl) — the text below is the trimmed reference that used to load into every request. The CLAUDE.md stanza for this subsystem keeps only the cross-cutting invariants; treat THIS file as the authoritative detail and keep it current the way you would CLAUDE.md.

- **Bedrock spend analytics** (`server/src/aws-costs.ts` + `src/components/home/CostsCard.tsx`) — daily USD stacked by user or by model, sourced by shelling out to the `aws` CLI (no SDK; mirrors how `dashboard.ts` shells out to `tailscale`/`pm2`). Deterministic software, zero AI. Route `GET /dashboard/costs?days=N[&refresh=1]`; CLI `con dashboard costs [--days N] [--refresh]`; store slice in `src/store/dashboard.ts` (`costs`, `costDays` localStorage `console:home:costDays`, `costStackBy` localStorage `console:home:costStackBy`). Home sub-tab `costs`; on desktop the card spans both grid columns (a time series needs the width). Pure aggregation unit-tested in `server/src/__tests__/aws-costs.test.ts`.
  - **THREE Cost-Explorer gotchas, each of which silently yields an all-zero chart** (all encoded in the module header): (1) **`SERVICE` is NOT `"Amazon Bedrock"`** — models are billed as AWS Marketplace products, one service per model (`Claude Opus 5 (Amazon Bedrock Edition)`); filtering on `Amazon Bedrock` returns $0. We therefore query **unfiltered by service** and classify client-side on the suffix (`parseBedrockModel`) — one CE request instead of two, and new model names appear automatically. (2) **`RECORD_TYPE` must be pinned to `Usage`** — promotional credits mirror usage to the cent, so the net `UnblendedCost` is exactly $0.00. (3) **`--profile` must be pinned** (default `default`, override `CONSOLE_AWS_PROFILE`): the `bedrock-amar` profile's IAM user has only inline `bedrock-invoke-only` and cannot call `ce:GetCostAndUsage`.
  - **Per-user attribution is the `owner` cost-allocation tag**, carried by application inference profiles (`<user>-cc-<model>`, tagged `owner=<user>` + `app=claude-code`; owners seen: `amar`, `guest1`, `sam`). Tagging a resource ≠ **activating** the tag key in Billing — `owner` was inactive until **2026-07-29** (`OWNER_TAG_EPOCH`) and activation does **not** backfill, so earlier days are unattributable by construction (the chart shades that region "no attribution") — permanent, no fix exists. A request against a **bare model id** (`us.anthropic.claude-opus-5`) routes around every profile and bills untagged — the translation layer below prevents that from this hub, so **`untagged` on a post-epoch day means spend that originated OUTSIDE this hub** (a shared IAM user's key driving an external `claude-cli` from another machine; fixing that needs its own per-person key + profile *there*). `untagged` is always its own explicit neutral-grey series sorted LAST (`rankKeys`) — never hidden, never folded into a person.
  - **`REGION_ATTRIBUTION` is the one escape hatch from the "tags never backfill" wall.** A region where exactly ONE workload consumes Bedrock lets untagged spend there be attributed with certainty rather than inference — including for days *before* that workload had a tagged profile, which CE itself can never recover. Currently `{'eu-west-2': 'deenai'}`: the agent fleet is entirely us-east-1, so eu-west-2 is **only** deen.ai's Lambda (`deen-wa-cloud`, ~$15-20/day). Costs a **second CE query** per fetch (`Tags: {Key:'owner', MatchOptions:['ABSENT']}` grouped by `[REGION, SERVICE]`; CE caps group-by at 2, hence two calls — issued via `Promise.all`, and the second is `.catch`-swallowed as non-fatal since without it the report is merely less attributed, not wrong). `MatchOptions` on a **Dimensions** filter only accepts `CASE_SENSITIVE|EQUALS|ABSENT` — `CONTAINS` 400s, so you can't filter to Bedrock by service-name substring; classify client-side as always. The move is **clamped to the day's actual `untagged`** so an inter-query mismatch can never push it negative or inflate a person, and reports `regionAttributedUsd` so the card can mark those figures `~` (region-derived, not tag-derived). Only add a region you have *confirmed* single-tenant — a wrong entry yields a confidently wrong chart instead of an obviously incomplete one.
  - **deen.ai spend is tagged `owner=deenai`** via its own application inference profile ARN in eu-west-2 (config in `~/proj/code/deen-ai/bot`; a full `update-function-configuration` rewriting its env is the one thing that would regress it — noted in that repo's README).
  - **The chart reads as PEOPLE, not tag values.** `CostReport.ownerNames` is a `tag value → display name` map computed hub-side per fetch: `BUILTIN_OWNER_NAMES` (`amar`→Yousef, `sam`→Sam, `guest1`→Lucas) merged under overrides from `~/.config/console/cost-owners.json` (read fresh every fetch, so a new person needs no restart). Only owners present in the window are included; `untagged` is never named. **Series/data keys stay the raw tag values** (stable CE join key + historical continuity) — only the Recharts `name` and the table label resolve to a person (`personName()` in `CostsCard.tsx`), falling back to the tag itself so a brand-new owner renders as its tag instead of vanishing.
    - **The ARN leaks back into the UI, so labels are a presentation layer** (`src/utils/model-label.ts`, `displayModel`). The CLI reports the ARN it was spawned with as the session's model, so `SessionInfo.model` is often an ARN — and the same model reaches the UI in four shapes (bare, `us.anthropic.`-prefixed, versioned, ARN). `modelLabel` regexes the family+version out of any id form; an ARN carries **no model name** and can't be reversed, so `displayModel(id, candidates)` resolves it against the option list the caller knows it asked for (single unique match wins, else `'Bedrock profile'`), falling back to the raw id so an unknown model never renders blank. **Labels never replace the value passed around** — the picker's `<option value>` stays the real id (the hub 400s on a label), the raw id/ARN lives in the `title` tooltip. `AgentTab`'s hub-wide picker keeps `FIRST_PARTY_MODELS` and `BEDROCK_MODELS` as **separate** lists, not one list plus a prefix: the same model needs a different id per backend and the wrong form 400s.
    - `scripts/switch-to-bedrock.sh` is now a **thin wrapper over `con agent backend set bedrock`** (waits for `/health` first). Never re-duplicate the model chain there — a duplicated copy drifted once and running it DOWNGRADED the fleet.
  - **`avgPerDayUsd` averages COMPLETE days only.** The window's last bucket is always today (`costWindow`'s `end` is tomorrow, so today's partial spend is inside the exclusive bound), and CE has only partially billed it — averaging it in makes the headline figure sag every morning and recover by night. `buildCostReport` splits it out as `todayUsd` + `avgDayCount`; the card shows `· $N/day` in the header (tooltip names the day count) and a dashed `ReferenceLine` on the chart.
  - **`CACHE_VERSION` in `aws-costs.ts` must be bumped whenever `CostReport` gains a field.** A report persisted by an older hub lacks the new key, and the UI renders `undefined` as **`NaN`** rather than failing loudly. Version mismatch → discard on load (currently **4**). The card also guards with `Number.isFinite` as a belt.
  - CE bills ~$0.01/request → `AwsCostStore` caches per-window on disk (`~/.config/console/aws-costs.json`) with a 6h TTL, dedupes in-flight calls, and serves a **stale report on error** so the card survives a briefly-unavailable AWS CLI. Bedrock **invocation logging is OFF** — that's the only other attribution route and it captures request content, so enabling it is Yousef's retention call.
