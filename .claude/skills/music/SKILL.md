# Music (Spotify via go-librespot)

Moved out of `CLAUDE.md` on 2026-09-08 (the CLAUDE.md diet, ^rosy-owl) — the text below is the trimmed reference that used to load into every request. The CLAUDE.md stanza for this subsystem keeps only the cross-cutting invariants; treat THIS file as the authoritative detail and keep it current the way you would CLAUDE.md.

Console is a **remote control over the Spotify Web API** — it handles **zero audio**; playback runs on the local **go-librespot** Spotify Connect device (`amarhp-spotifyd`, systemd user service `go-librespot.service`, config `~/.config/go-librespot/config.yml`, zeroconf, pulseaudio/PipeWire backend, local control API on `127.0.0.1:3678`). go-librespot needs a one-time zeroconf Connect handoff to cache credentials (pick `amarhp-spotifyd` in a Spotify app once). **Not a pane** — a global right-side **drawer** (Music icon in the Layout header). See `memory/project_spotify.md`.
- **Hub** `server/src/spotify/`: `client.ts` (Web API wrapper — devices, player, play/pause/next/prev/seek/volume/shuffle/repeat/transfer/queue, search, playlists, library add/remove, saved-tracks; auto-resolves the spotifyd device as the default control target), `store.ts` (`SnapshotStore` now-playing snapshot), `sync.ts` (poller), `types.ts`. Routes `server/src/routes/spotify.ts` (`/spotify/*`).
- **Auth** (`auth-store.ts` Spotify block + `routes/auth.ts` `/auth/spotify/*`): OAuth **Authorization Code, confidential client** (hub holds the secret, HTTP Basic to the token endpoint), proactive refresh. Creds + tokens in `auth.json` under `spotify`. Redirect URI **`https://con.amar.io/hub/auth/spotify/callback`** (note order: `auth/spotify`, NOT `spotify/auth`). Set creds via `POST /auth/spotify/credentials`; link via `GET /auth/spotify/start` (browser; needs a Spotify **Premium** account + the app's User Management allow-list in dev mode).
- **Poller is gated** on `syncBus.subscriberCount('spotify') > 0` — it only hits Spotify while a drawer is open (Spotify has no realtime push); control actions call `sync.pokeSoon()` for a fast refresh. The drawer interpolates progress between snapshots from `fetchedAt`.
- **Two Spotify-API gotchas (load-bearing)**: (1) player-control endpoints (play/pause/next/seek/…) now return **HTTP 200 with a bare command-id string, not 204** — `client.request()` only JSON-parses responses whose `content-type` is `application/json`, else returns null. (2) **shuffle/repeat support is device-dependent** — go-librespot supports them (snapshot `actions.disallows` empty → drawer buttons enabled, CLI works); The UI is driven entirely by `actions.disallows`, so it adapts per device automatically. **DJ mode is app-only** (no Web API) — not available.
- **SPA**: `src/store/music.ts` (Zustand), `src/music/live.ts` (SyncBus `spotify` `delta` + HTTP initial load — subscription wired only while the drawer is mounted, which is what gates the poller), `src/components/music/MusicDrawer.tsx` (now-playing, transport, volume, device, search-to-play, like/❤, Library = Liked Songs + playlists with click-to-play and +add-current). Music icon + `{musicOpen && <MusicDrawer/>}` in `Layout.tsx`; store-backed `open` toggle; Esc closes.
- **CLI** `con music` (`cli/src/commands/music.ts`): `now|status|play|pause|next|prev|toggle|vol|seek|shuffle|repeat|devices|transfer|search|playlists|liked|queue|add|remove|like|unlike`. `play` no-arg = play/pause toggle (fetches fresh state); `play --playlist/--album/--artist "<name>"` plays a context by name; `play "<text>"` plays the top track. **This is the system-wide media-key target** — `XF86AudioPlay/Next/Prev` → `con music play/next/prev` (owned by the `System general` agent's Sway config; cold-start play works, which MPRIS/playerctl couldn't once spotifyd goes idle).
