# Google Maps overlay

Moved out of `CLAUDE.md` on 2026-09-08 (the CLAUDE.md diet, ^rosy-owl) — the text below is the trimmed reference that used to load into every request. The CLAUDE.md stanza for this subsystem keeps only the cross-cutting invariants; treat THIS file as the authoritative detail and keep it current the way you would CLAUDE.md.

Goal: search Google Maps locations and overlay directions on the Map tab so it can replace day-to-day Google Maps use — **without** dropping the MapLibre+OpenFreeMap basemap (Google results are *overlaid*, tiles stay OFM). On mobile the ask is narrower: find places + "Open in Google Maps" deep link for actual navigation (the phone already has the app).
- **Provider = Google Maps Platform** (Places API New + Routes API), one Cloud key. **The key never reaches the browser** — the hub proxies everything under `/gmaps/*` and the key is stored server-side in `auth.json` (`googleMaps.apiKey`, via `AuthStore.getGoogleMapsKey/setGoogleMapsKey/clearGoogleMaps`; status exposes `{configured}` only). Set it with `con map gmaps credentials --key <AIza…>` / clear with `--clear`, or the in-panel key form (shown when `gmapsConfigured === false`). The key must be a **real Maps Platform key (starts `AIza`)** — an OAuth2 token (`AQ.Ab8…`) 401s with "API keys are not supported by this API". Places API (New) **and** Routes API must be enabled in the Cloud project with billing on, or you get a 403 "has not been used in project … before or it is disabled".
- **Hub** `server/src/gmaps/client.ts` (`GoogleMapsClient`, ctor takes `AuthStore`): `searchText(query, bias?)` → `POST places:searchText` (text search, region-biased `gb`, viewport `locationBias` when a center is passed); `autocomplete(input, {lat,lon,radiusMeters,sessionToken})` → `POST places:autocomplete` (type-ahead); `placeDetails(placeId, sessionToken?)` → `GET places/{id}` (resolve a suggestion to a full place); `computeRoutes({origin,destination,travelMode,alternatives,departureTime?})` → `POST directions/v2:computeRoutes`. Field masks are explicit (`X-Goog-FieldMask`). Routes asks for `computeAlternativeRoutes:true` + `polylineEncoding:'GEO_JSON_LINESTRING'` so geometry drops straight onto MapLibre with no polyline decode; duration is a protobuf `"1234s"` string (`parseDurationSeconds`). **`routingPreference:'TRAFFIC_AWARE'` is DRIVE-only** — sending it for WALK/BICYCLE/TRANSIT 400s. **`departureTime` (RFC3339 UTC) is only ever sent for TRANSIT** — it's the only mode whose result is schedule-dependent (property/airport-distance.ts's `nextWeekdayMorningUtc()` is the one caller that sets it, to avoid a poller landing on a dead-of-night query).
- **Client helpers live in `src/utils/gmaps.ts`** (since 2026-10-03, ^deft-bass): `autocompletePlaces(q, bias?)`, `fetchPlace(placeId)`, `placeLocationText(place)` ("Name, address" the way Google Calendar fills its location field), `gmapsConfigured()` (one cached `/gmaps/status` probe per page load), `lastKnownLocation()` (`GET /location` fix, cached 10 min — the bias when no map is mounted), plus the `GPlace`/`GSuggestion` types (re-exported from `src/store/map.ts` for the Map tab). **Autocomplete session tokens**: a `crypto.randomUUID()` token (module-level in `utils/gmaps.ts`) is sent on every keystroke AND to the follow-up `fetchPlace`, grouping them into ONE billable Google session; `fetchPlace` rotates it. Callers debounce 250 ms, guard `q.length < 2`, and drop stale responses. **`src/components/PlaceAutocomplete.tsx`** is the reusable input (type-ahead dropdown, arrow/Enter/Tab/Escape, biased to the phone fix, degrades to a plain input when no key is configured); the calendar event form's Location field uses it — picking a suggestion writes `placeLocationText` into the plain `location` string Google Calendar stores.
- **Routes** `server/src/routes/gmaps.ts`: `GET /gmaps/status`, `POST /gmaps/credentials`, `DELETE /gmaps/credentials`, `GET /gmaps/search?q=&lat=&lon=&radius=`, `GET /gmaps/autocomplete?q=&lat=&lon=&radius=&session=`, `GET /gmaps/place/:placeId?session=`, `POST /gmaps/directions {origin,destination,mode,alternatives,departureTime?}`. Wired in `index.ts` (`const googleMapsClient = new GoogleMapsClient(authStore)` + `if (path.startsWith('/gmaps') && handleGmapsRoutes(...))`). CLI `cli/src/commands/gmaps.ts` (`con map gmaps {status,credentials,search,directions}`; `directions` takes `--departure <RFC3339>`; second word = the Map tab).
- **Client render**: search pins + routes are **ephemeral client-store sources** (`gmaps-pins`, `gmaps-routes` in `MapTab.tsx`), NOT persisted agent layers — like geocache/meetup pins. Store slice in `src/store/map.ts` (`gmapsConfigured/gmapsResults/gmapsSuggestions/gmapsRoutes/gmapsSelectedRoute/gmapsSelectedPlaceId` + `searchGmaps/autocompleteGmaps/pickSuggestion/selectPlace/getDirections/selectRoute/clearGmapsSearch`). UI is `GmapsPanel` (search box + type-ahead dropdown + results + directions with travel-mode toggle + route alternates) and `PlaceDetailPanel`, both with an "Open in Google Maps" deep link (`gmapsDirUrl`). The panel reads the map center via `mapController.center()` (added to `src/map/controller.ts`) — no map ref leaks into the panel.
