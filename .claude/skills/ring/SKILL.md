# Pebble ring voice commands

Moved out of `CLAUDE.md` on 2026-09-08 (the CLAUDE.md diet, ^rosy-owl) — the text below is the trimmed reference that used to load into every request. The CLAUDE.md stanza for this subsystem keeps only the cross-cutting invariants; treat THIS file as the authoritative detail and keep it current the way you would CLAUDE.md.

A smart ring with one button + a mic (Core Devices; single click-hold = the ring's own note agent, double click-hold = configurable). Its app can POST every recording to ONE webhook **in addition to** its own agent run, and **never shows the HTTP response** — so Console's feedback is a push notification, never the reply body. Docs: `https://help.repebble.com/en/articles/15724406-index-advanced-features-mcp-webhook`. Yousef's intent: a `con`-like tree of short commands, spoken to **projects and lists, not agents** — `log dream …`, `add movies …`, `add console …`, `message mum …` — AL as the final fallback. **There is deliberately NO `agent <name>` verb** (Yousef's rule — an early version had one and was rejected) — `add <project> …` files a card and the board forks the agent; AL is reached only as the unclaimed-text fallback.
- **Wire shape**: `POST https://con.amar.io/hub/ring/webhook`, `multipart/form-data` with parts `audio` (`audio/mp4`, M4A, ≤~2 min), `transcription` (text — ABSENT when the ring's STT failed, so it must be optional), `recordedAt` (ms epoch), `client` (`ring`); header `X-Audio-Size` when audio present, plus user-defined headers. Auth = the normal wall: `con ring setup` mints a **`ring`-scoped bearer** (`HubTokenScope`) and prints the URL + `Authorization: Bearer …` to paste into the Pebble app. Nothing under `/ring/*` is exempt. `POST /ring/webhook` also accepts JSON `{transcription|text}` — that's `con ring say "<text>"`, which runs the FULL pipeline (archives a recording, executes — a "play" resumes Spotify, a "message" sends). The schema dev loop is `con ring say --dry` → `POST /ring/dry-run` (`dryRun()` in pipeline.ts: the same rules → LLM → fallback decision, nothing archived or executed).
- **Hub** `server/src/ring/`: `multipart.ts` (pure Buffer-walking parser + `buildMultipart` — NOT the `toString('binary').split()` hack `/stt` uses), `store.ts` (`RingStore` → `~/.config/console/ring/recordings/<id>.m4a` + `<id>.json` sidecar; ids sort chronologically; **append-only, no delete/prune API** — posterity), `schema.ts` (the tree as DATA — see below), `schema-loader.ts` (hot-reload from the vault, last-good on a broken edit), `router.ts` (PURE rules), `append.ts` (pure note edits: dated log bullet / list bullet / movie table row), `llm-fallback.ts` (`claude -p` on `smallFastModel()`: the classifier + the movie enricher; strict JSON, off-schema → null), `pipeline.ts` (`processDelivery`: archive → transcript → route → execute → notify; every hub touchpoint via `RingCtx` so it's stub-testable — `server/src/__tests__/ring.test.ts`). Routes `server/src/routes/ring.ts`: `/ring/{webhook,status,schema,recordings[?limit],recordings/:id,recordings/:id/audio}`; ctx wired in `index.ts` beside `configDir` (must sit AFTER `configDir` — TDZ). CLI `con ring {status,setup,list,show,audio,say,schema}`.
- **The command tree lives in a vault note, `projects/console/ring-schema.md`**. Handlers are code (a new *kind* of action is code anyway); the note's ```yaml fence owns the PHRASING, and **every entry is `canonical: [ways to say it]`** (the parser REJECTS a string-valued contact shape rather than silently inverting it): `fallback`/`llm_fallback`; `add.aliases` (`log` is one of them — see below), `add.targets` (`name: {file?, dated?, enrich?, aliases}`; `file` defaults to `scratch/lists/<name>.md`, a bare `name:` is a plain list), `add.project_column`; `start.{aliases,column}`; `message.aliases` + `message.contacts` (`users/<name>.md` username → spoken forms); `echo.aliases`; `music`. The parser also flags a spoken form claimed by two targets or two contacts. **Lists and logs are ONE thing** (Yousef's rule): a note under `scratch/lists/` we append a bullet to; `dated: true` makes it a log (`## YYYY-MM-DD` heading per day + `- HH:MM text`), so `log dream …`/`log journal …`/`log emotion …` (alias `system` for discretion) and `add groceries …` are the same verb with different targets — a mis-heard add↔log costs nothing. Existing lists keep their filenames via explicit `file:` (`movie-list.md` etc.). The live note's contacts (12 people, ~50 spoken forms) are populated from AL's `users/*.md`; the repo's `seedSchemaNote()` keeps a generic placeholder on purpose (public repo). Emotion-log semantics are a separate future card. `RingSchemaLoader` re-reads it on every delivery (tiny file), **seeds it from `seedSchemaNote()` when missing, and keeps the LAST GOOD schema when the yaml is unparseable** — a mid-edit typo must not flip routing to defaults. `con ring schema` prints the effective tree with every target resolved (file exists / project known / contact in AL's workspace / agent live); `--check` exits 1 on parse errors or unresolved targets. Parse errors also ride `GET /ring/status.schemaErrors`.
- **Transcript precedence**: ring's `transcription` → else hub batch STT on the audio (`al/transcribe.ts` `transcribeAudio`, `audio/mp4`) → else archived with a "no transcript" push and no routing. Sidecar records `transcriptionSource: 'ring'|'hub-stt'|null`.
- **Routing — deterministic first, LLM last, by Yousef's design.** `normaliseKeepCase()` (NFKC, curly quotes, leading fillers `hey/ok/um/please…`, trailing punctuation) — matching runs on its lowercase form, **payloads keep the speaker's case** (a dream log shouldn't read all-lowercase). Shape `<verb> <target> <payload>`: the first word resolves to a verb by name, schema alias, or ONE edit (`fuzzyEqual`: words ≥4 letters only, optimal-string-alignment distance so an adjacent swap like `flims` is one edit; `pickFuzzy`/`resolveSpoken` never guess between two canonicals — fuzzy hits on two forms of the SAME canonical still count as unique), the second word to a target through its alias table the same way, the rest is payload. **Trailing-target fallback**: when neither a list nor a project resolves from the second word, `splitTrailingTarget` re-reads the payload as `<item> to [the|my] <target> [list]` — every `to` split, left to right, first resolving one wins ("Add Count of Monte Cristo to movie list" → movies; "add export to csv to reflection tools" → the project card). It is a FALLBACK by design: a first-word target still wins, so "add movies Journey to the Center of the Earth" keeps its full title. **A FUZZY verb hit with an unknown target is NOT a command** — it falls through to the LLM/fallback; only an EXACT verb/alias with a bad target gets the "no such target" push. Rules (`rule` recorded in the sidecar): `add.log` (dated target) → `appendLogEntry` (`## YYYY-MM-DD` + `- HH:MM text`, both from the **LOCAL** clock; the server suite pins `TZ=Europe/London` so local-date assertions can't depend on the runner); `add.list` → **a raw pipe-table row, stamped** (`ring/table.ts` `appendRow`: `| Item | Added |`, or the enricher's columns — movies `| Title | Year | Series | Watched | Added |`; a table missing columns is migrated in place, header + every row; no table → one is started after the existing content). **Enrichment is a SEPARATE step and a property of the FILE, not the ring** (Yousef's rule; it lives in **`server/src/lists/`** and the CLI is **`con notes enrich`** → `POST /notes/lists/enrich`): `lists/watcher.ts` `ListWatcher` polls the vault (`NoteStore.listSince`, the BoardWatcher primitive) for changes to any list note whose target declares `enrich:`, gathers the rows the enricher calls pending, hands them over in ONE batch, and applies the results — `fill` cells, or `remove` the row (queue semantics) and append a dated line to a log note. Enricher registry `lists/enrichers.ts`: **`movie`** (`claude -p` canonical title/year/series; pending = title without year); **`grocery-order`** — **the groceries list is a QUEUE**: `sainsburys order status --json` → no `active` order or past `is_cutoff` → every row `skip` with `retry:false` (not a failure, just "not yet"); open order → `order amend <order_uid>` unless already `is_in_amend_mode`, then per item `product search` → the LLM picks among the top 6 hits (or says none; no LLM → top hit) → `basket add <sku> -q 1 --slot-booked`, then **ONE `checkout --yes --headless --slot-booked`** confirms the amendment (a real browser, minutes) — only then do rows leave the list, each logged as `- HH:MM <item> → <product> (order <id>)` in `scratch/lists/groceries-ordered.md`; checkout failure → nothing leaves (items sit in the basket, amend unconfirmed), rows back off. **It never books a slot or places a fresh order — the weekly cron owns that**, and `~/exec/grocery-usuals.sh` now ends with `con notes enrich` so the queue drains the moment an order exists. Watcher mechanics: 5 s quiet debounce (half-typed row), per-row 1 h backoff only for `retry:true` skips, a 30-min sweep re-examines every list so queue drains happen when an order opens even with no file change, boot sweep, `con notes enrich` forces a pass; results are applied against a fresh read and rows located by content, never by old index; its write bumps the note's mtime, so an open editor buffer hits the normal conflict dialog. `add.card` → `BoardOps.add` on the project board (`project_column`, default Backlog = queued — a project slug as the target, and only projects WITH a board are candidates so ~70 board-less vault slugs stay out of the fuzzy match; hyphenated two-word slugs like `reflection tools` work); **`start <project> <text>`** (aliases `do/go/kick/begin/now`, `verbs.start.column` default In Progress) = the same card but straight into the dispatch column, so the BoardWatcher forks an agent for it NOW — this is how Yousef "contacts a project": `add` to backlog it, `start` to kick it off; `message` → **sent AS YOUSEF through his own Matrix account** (`matrixSync.sendRoomEvent`, encryption-aware — the `con chat send` path; Yousef's rule — never relay via AL); **`al` is a built-in contact** (`AL_CONTACT` — he has no `users/*.md`, that list is HIS contacts; the resolver uses `alWa.ownIdentifiers()` — phone + lid — instead, so `message al …` lands in AL's WhatsApp DM from Yousef's account and AL answers on WhatsApp). **Do NOT reroute `message al` to `al.direct`** (Yousef's rule; it was shipped once on a card's say-so and reverted the same day); the bare `al <text>` verb is the conversation path, `message al` is a send; every other contact's DM room is resolved deterministically by `ContactRoomResolver` (`ring/chat-room.ts`): direct WhatsApp rooms from `chatRoomsStore` whose member list (room state, cached per room) contains the bridge ghost for one of the contact's `users/<name>.md` ids — `@whatsapp_<phone>:beeper.local` or `@whatsapp_lid-<lid>:beeper.local`. **The ghost may be keyed by lid even when the note only records the phone**, so `chatSendAsYousef` first runs the ids through `expandIdentifiers()` (same file): each phone is mapped to its lid via AL's Baileys socket (`alWa.lidForNumber` → `signalRepository.lidMapping.getLIDForPN`, populated as AL sees the contact; `alWa.ownIdentifiers()` = his own phone + lid). A miss after that means AL has never seen the contact's lid — add it to their `users/<name>.md`; no room → "not delivered" push, never a fallback; `tell`/`text`/`whatsapp` are default aliases; **`al <text>`** (or any of AL's spoken forms from the note, exact match only) is the ESCAPE HATCH: straight to the `AL ↔ ring` fork, skipping the tree AND the classifier (the classifier rescues mis-heard TREE commands; this is explicitly not one); **`echo <text>`** (aliases `test/ping/repeat`) → the payload goes to Yousef's OWN WhatsApp via AL's socket (`alWa.sendText` to `NOTIFY_JID` from `server/.env`, else the first id in `users/yousef.md`) — pure software, no LLM, no fork: the end-to-end smoke test; music transport = a WORD-SET match (`matchMusicTransport`: ≤4 words, every word an action word or filler, exactly one action — the STT gives "Music plays." as readily as "play music"; bare `on/off/back` need the noun), plus `play <query>` → top Spotify track (`musicQuery` drops "some/me", a spoken noun and a matched pair of wrapping quotes), optionally addressed (`Music, play X`); checked BEFORE the verb tree so a bare `play` isn't a verb with a missing target. **Head punctuation is handled ONCE, for every rule** (`headWords(cased, n)`): the STT decorates the command head every which way (`Log dream.`, `Music, play`, `Al: …`, `Message Nica — …`, `Music… pause`), so each rule reads its address word / verb / target through the one tokeniser, which drops trailing `, . : ; ! ? …` and skips free-standing dashes, while `rest` (the payload) is returned exactly as spoken — a dream log keeps its full stops. `matchMusicTransport` cleans its word set the same way (`cleanWords`), and two-word project slugs clean the payload's first word. Never add a per-rule `[,.:]?` or a verb-specific vocative regex again — extend `HEAD_PUNCT` instead. **A matched verb with an unknown target is `unknown-target`**: a "no log target called X — add it to the schema note" push, never a fallback to AL (mis-hearing a target shouldn't hand a garbled command to an agent). Only when NO verb fires: `llm_fallback` → `classifyWithLlm` (may only pick targets from the schema/env; off-schema → no match) → `fallback` agent (`kind:'fallback'`; AL by default) → `unknown`. **Ring work for AL never lands in his main session**: `deliverToAl` routes fallbacks through the existing conversation-fork machinery (`al/conversation-forks.ts` `routeInbound`, thread key `'ring'`, fork named `AL ↔ ring`, idle wind-down → digest-merge into parent) with a ring-specific seed (`buildRingForkSeed`, passed via `routeInbound`'s new `opts.seed`) — the seed carries the current tree and the standing instruction: act on the unclaimed transcript, then if it SHOULD have been a tree command, `con spaces board console add "Ring schema gap: <transcript> → <mapping>"` (never edit the schema note itself — Console general owns it). Parent AL is the last resort only when the fork can't spawn. A non-AL `fallback` key is injected directly (no fork). `route.via` (`rule|llm|default|none`) + `rule` land in the sidecar so the tree can be tuned from `con ring list`.
- **Execution feedback**: result → `pushServer.broadcast` (`type:'generic'`, id `ring:<recId>`). A dead target is reported ("X is not live"), never silently swallowed. **Failures also land in the Home alerts log** (Yousef's rule) — `RingStore.failures(sinceMs)` (no transcript, or `route.ok === false`) feeds `gatherAlerts` via the dashboard ctx's `ringFailures` as `kind:'error', source:'ring'` rows, 24 h window. **And a failed route files a board card the moment it happens** (Yousef's rule): `fileMissCard` (index.ts) adds `Ring miss: "<transcript>" → <detail>` to the console board in `on_failure.column` from the schema note (default **In Progress**, so the board dispatches a Console-general fork immediately; `Backlog` = triage; `null` = off), with detail lines from `buildMissCard` — the recording id + `con ring show`, then **step 1: interpret the transcript and DO what Yousef asked** (check the sidecar first so a partly-done action isn't doubled), **step 2: fix the cause** (schema note phrasing / target, or `server/src/ring/` / `server/src/lists/`), verify with `con ring say --dry` + `con ring schema --check`. Deduped on the board itself: an OPEN card (any column but Done) whose text starts with `Ring miss: "<same transcript>"` means no new card (`route.card` in the sidecar records `filed|exists|failed`). `kind:'unknown'` (no fallback configured) is a choice, not a miss — no card. Unclaimed text still goes to the AL fork, whose seed asks IT to judge whether a `Ring schema gap` card is warranted. Latency: rules are µs; hub STT 1–3 s only when the ring sent no transcript; the LLM classifier ~10–15 s only on a rule miss (`llm_fallback: false` skips it).
- **Recommended ring config**: Send = both, Trigger = the button combo reserved for Console (double click-hold) so plain notes never hit the fallback agent. Not built: an MCP-sandbox server (the ring's cloud agent calling Console tools — Yousef wants string parsing, so the webhook is the primary path); SPA/APK surfaces for the archive (`con ring list/show/audio` is the current reader).
