# Geocaching + Meetup map sources

Moved out of `CLAUDE.md` on 2026-09-08 (the CLAUDE.md diet, ^rosy-owl) — the text below is the trimmed reference that used to load into every request. The CLAUDE.md stanza for this subsystem keeps only the cross-cutting invariants; treat THIS file as the authoritative detail and keep it current the way you would CLAUDE.md.

### Geocaching subsystem (pycaching port — `server/src/geocaching/`)
The hub scrapes **geocaching.com as Yousef himself** (the c:geo model — the official partner API is closed to individuals; the open Opencaching dataset is too thin for the UK). A from-scratch TypeScript port of the Python `pycaching` library. See `memory/project_geocaching.md`.
- `session.ts` — cookie jar (`geocaching-session.json`, 0600) + **manual redirect following** (Node `fetch` has no jar). Login via `/account/signin` + `__RequestVerificationToken`; success = `"username":"…"` in page JS. **reCAPTCHA often blocks programmatic login → cookie fallback** (paste browser `gspkauth`). **Premium matters** — PM-only caches otherwise 403 the detail scrape.
- `client.ts` — **search-first**: `/api/proxy/web/search/v2?box=N,W,S,E` → ~200 summaries/request (`cacheFromApiRecord`, verified pycaching mapping). Full detail (hint ROT13, attributes off image filenames, logs via `/seek/geocache.logbook?tkn=<userToken>`) is **lazy**, only on cache open — keeps request volume + ban risk near zero.
- `rate-limit.ts` — safety core: concurrency 1, jittered 3–6 s delay, persisted **daily budget** (default 400, `geocaching-budget.json`), 429 backoff. **Manual-trigger only — no background gc.com polling.**
- `parse.ts`/`types.ts` — pure, unit-tested (`server/src/__tests__/geocaching.test.ts`); enum ids ported verbatim from pycaching.
- Routes `server/src/routes/geocaching.ts`: `/geocaching/{status,credentials,fetch-area,caches,cache/:code}`. CLI `con map geocaching {status,config,fetch,caches,cache}` (second word = the Map tab). Log text is HTML-stripped server-side (`htmlToText` in `parse.ts`) + client-side (`stripHtml` in `MapTab.tsx`).
- **Upstream-watch cron** (id `dAnazbI`, weekly Mon 09:00, bound to a fixed claudeSession) checks `pycaching/releases.atom` vs `geocaching-upstream.json` and folds upstream fixes into the port. Works on a Basic account; PM-only caches return as coordless stubs (~48% in a Reading radius) — Premium roughly doubles usable coverage but isn't required.
### Meetup events subsystem (`server/src/meetup/`)
Meetup events as a Map-tab layer (📅 pins), modelled on the geocaching subsystem but **anonymous** (no Pro subscription, no OAuth, no login). See `memory/project_meetup.md`.
- **No official API needed.** Meetup's web GraphQL endpoint `https://www.meetup.com/gql2` (fallback `https://api.meetup.com/gql-ext`) answers **anonymously** with full introspection. The official API requires **Meetup Pro** (~$55/group/mo; Meetup+ is a consumer perk and grants *no* API access) — we don't use it.
- `client.ts` — `MeetupClient` (ctor: `configDir`). `eventSearch(filter: EventSearchFilter!, first, after)` returns events with **venue `lat`/`lon` inline + a pagination cursor** in ONE request — no per-event detail hop for coords, no HTML scrape, no geocoder. `query` is **required (String!)**; empty → 0 results, so "everything near here" = `query:"*"` (a real keyword just filters). `fetchArea({lat,lon,radiusMiles,query?,eventType?,startDate?,endDate?,categoryId?,maxPages?})` paginates up to `maxPages` (default 4, ~PAGE_SIZE 50/page), `startDateRange` defaults to now (upcoming only). `getEventDetail(id)` = lazy `event(id:ID!)` for the long description. `eventType` enum = `PHYSICAL|ONLINE|HYBRID`; online/hybrid events have **no venue → no pin**. `radius` is **miles** (caps ~100). GraphQL errors are non-retryable; transport failures retry on the fallback endpoint.
- `store.ts` — `MeetupEventStore` keyed by event id, atomic JSON at `~/.config/console/meetup-events.json`. **Time-bound: `prune(now)`** drops ended events (endTime, else start+3h, else never) on load + each snapshot — the key difference from geocaches.
- **rate-limit** reuses `geocaching/rate-limit.ts` `RateLimiter` (now takes an optional `label`): concurrency 1, 1–2 s jitter, daily budget **800** (`meetup-budget.json`). **Area choice is manual-trigger only** — but `server/src/meetup/sync.ts` (`MeetupSync`, wired in `index.ts`) re-runs the LAST manual fetch-area once a day (`meetup-refresh.json`: spec persisted by `MeetupClient.fetchArea`, date windows re-anchored as `days` durations). Why: the store prunes ended events, so without a refresh a one-off fetch starves to zero within days and the SPA calendar overlay unregisters on empty. Never fetched = never polls; 1–4 req/day vs the 800 budget. A fetch = 1–`maxPages` requests.
- `types.ts` — pure `eventFromNode` / `isExpired` / `eventEndMs`, unit-tested (`server/src/__tests__/meetup.test.ts`). No `session.ts` (anonymous).
- Routes `server/src/routes/meetup.ts`: `/meetup/{status,fetch-area,events,event/:id}` (`fetch-area` accepts `{bbox}` or `{lat,lon,radiusMiles}` + `query/type/days/startDate/endDate/categoryId/pages`; bbox→center+radius-miles via `centerRadiusFromBbox`). SyncBus `meetup` service (snapshot + `delta` summaries) wired in `index.ts` beside geocaching. CLI `con map meetup {status,fetch,events,event}` (second word = the Map tab). Client mirror `src/meetup/subscribe.ts` (Dexie `meetupEvents` **v11** + SyncBus `meetup`, offline-first) → `useMapStore` (`events`, `fetchMeetupArea`, `selectEvent`, `meetupDays/meetupHideOnline`). MapTab: `meetup-pins` symbol layer (📅) + `meetup-selected` ring + `MeetupEventPanel` (lazy detail) + toolbar group (time-window / fetch-here with budget; keyword box dropped — fetch always wildcards, keyword via `con map meetup fetch --query`). The Map shows only events **with coords** (physical + hybrid-with-venue); online events have no coords and live in the Calendar overlay (below) — there is no hide-online toggle.
- **Calendar overlay (online events have nowhere on a map):** physical events pin on the Map; **all** events (incl. online/hybrid, which have no venue → no pin) also surface in the **Calendar tab** as a read-only synthetic "Meetup" calendar via the generic `registerOverlaySource` seam (see Calendar section). `src/meetup/calendar-overlay.ts`: pure `meetupEventToCalendarEvent` adapter + `wireMeetupCalendarOverlay()` (subscribes `useMapStore.events`, wired in `GatedBoot`). **No "Add to Calendar"** — Yousef's Meetup booking emails already create real GCal events.
