# G1 glasses

Moved out of `CLAUDE.md` on 2026-09-08 (the CLAUDE.md diet, ^rosy-owl) — the text below is the trimmed reference that used to load into every request. The CLAUDE.md stanza for this subsystem keeps only the cross-cutting invariants; treat THIS file as the authoritative detail and keep it current the way you would CLAUDE.md.

Wire protocol + firmware-derived opcode maps: `docs/g1-protocol.md` (§17 opcode map, §18 nav, §19 primitives, §20 teleprompter, §21 timer), `docs/g1-future-ideas.md`, `docs/g1-mic-stt-recipe.md`.

- **Native Kotlin BLE**, not Web Bluetooth. APK-only. See `docs/g1-protocol.md` for the wire protocol (NUS UUIDs, opcodes `0x4E` text / `0x15+0x20+0x16` BMP / `0x25` heartbeat / `0x0E` mic / `0xF5` touchbar / `0xF1` audio / `0x4B` notification).
- Dual-arm: every non-BMP command goes to L, waits for `0xC9` ack, then R. BMP upload fans out L+R in parallel.
- `GlassesService` — second Android foreground service (type `connectedDevice`), sibling to `PushService`. Lives in same process so they share memory via `GlassesState` singleton; communication is free.
- **Phone is single source of truth** for connection state. Hub RPCs the phone on demand; no constant state pushes.
- Hub exposes `/glasses/*` (dumb pipe: text, bmp, clear, notify, mic, status, disconnect, scan). Phone proxies each call to BLE. Pairing happens phone-side only; scanning can be triggered from the hub too (APK v6+).
- WS RPC framing on `/push` — `{type:'rpc_request',id,method,params}` hub→APK, `{type:'rpc_response',id,ok,result|error}` APK→hub, and unsolicited APK→hub streams: `glasses_state` (snapshot), `glasses_audio` (LC3 frames while mic is on), `glasses_touch` (touchbar events), `glasses_frame` (research-log raw frames, see below), `glasses_scan_observation` (every named BLE advert seen during a scan — diagnostic, regardless of G1 regex match). Hub side in `server/src/glasses-hub.ts`; APK side in `PushService.handleHubRpc` / `bleListener`.
- CLI: `con glasses {status,text,clear,bmp,notify,mic,disconnect,scan,research}` — see `cli/src/commands/glasses.ts`.
- **Scan diagnostics (APK v6+)**: `con glasses scan start` triggers a BLE scan phone-side; `con glasses scan observations` dumps the most recent named advertisements the APK saw — use this when the UI says "no glasses" to confirm whether the G1s are advertising at all or advertising under a different name. `BleManager.scanCallback.onScanFailed` surfaces scan errors to `GlassesState.lastError`. Scan observations also echo into `glasses-research.log` with `kind: 'scan_observation'`.
- SPA: `src/glasses/bridge.ts` wraps the `ConsoleNative` JS bridge, `src/glasses/store.ts` is the Zustand store, Settings UI is in `src/components/GlassesSettings.tsx`. All no-ops in the browser (only the APK exposes the bridge).
- **App-wide mirror** (`src/glasses/mirror.ts` + `src/glasses/panes/*.ts`): single "Mirror current tab" toggle in Glasses settings renders whichever pane is active (email, chat, agents, calendar, feeds, notes, bookmarks, money) onto the lenses at 5 rows × 40 cols — row 1 is a `Pane · focus · meta` status line, rows 2–5 are per-pane body. Per-pane renderer in `panes/<name>.ts` returns `{status, body}`; `mirror.ts` pads/clips and writes via `ConsoleNative.glassesSendText`. Notes renderer keeps the cursor-follow behaviour (cursor on row 3 or 4, `|` glyph at col, wrapped with line numbers) shrunk to 4 body rows. Chat/Agents reserve row 5 for a composer echo (`> …|`) fed by `useGlassesStore.composerText` — the uncontrolled textareas in `ChatComposeInput`/`AgentPromptInput` push on every keystroke so the lens reflects what the user is typing. 30 ms coalescing debounce, frames deduped against the last send. Persisted via localStorage (`console:glasses:mirrorEnabled`). Subscriptions for all eight panes + active-pane + composerText wired once in `wireMirror()` via `wireGlassesStore()`.
- **Mirror "stealth screen"**: turning the mirror toggle on calls `ConsoleNative.setMirrorDim(true)` which holds `FLAG_KEEP_SCREEN_ON` and sets `screenBrightness = 0.01f`. The panel looks off but the Activity stays foreground so HW-keyboard keystrokes keep reaching the WebView. Re-applied on boot in `wireGlassesStore()` when the persisted toggle is on.
- **Notifications → glasses + idle HUD**. Two display layers on top of the SPA mirror, no central compositor:
  - **Notifications**: every hub push (`pushServer.broadcast`) also fans out to the lenses as a **native `0x4B` firmware card** (firmware renders + self-dismisses). Wiring: `pushServer.onBroadcast(handler)` → `server/src/glasses/notify-forward.ts` (`makeNotifyForwarder` maps `PushMessage`→`{title,message}` per type, `mapPushToCard`) → `glassesHub.notify()` → APK `handleHubRpc("notify")` → `0x4B`. **The hub owns the card `msgId`** (`GlassesHub.allocMsgId`, rolling 1..255, returned by `notify()`); `POST /glasses/notify/dismiss {msgId}` → `0x4C` (`con glasses notify dismiss <id>`; the ack is unconditional, ok ≠ "a card existed"). Siblings from the same firmware read (`docs/g1-protocol.md` §19): `GET /glasses/status` gains `runningApp` via a `0x39` query (0 = idle, NOT 0xFF), and `con glasses unpair --confirm` → `0x47` (destructive). None of the three has been on the wire yet — first real invocation is the verification, `con glasses research tail` right after. Gated by `GlassesConfig` (master + per-channel) + the global DnD pref (`prefsStore.getAll().dnd`). Cancels are dropped (firmware card self-dismisses). **Load-bearing: the `0x04` app-whitelist** — firmware silently drops `0x4B` for non-whitelisted app ids, so `BleManager` sends `G1Protocol.encodeAppWhitelistChunks(defaultWhitelistJson())` on connect (single id `io.amar.console`; the source label rides `0x4B display_name`).
  - **HUD**: idle dashboard shown on **head-tilt up** (`0xF5 0x02`, right arm), cleared on `0x03`. Hub-driven: `server/src/glasses/hud.ts` `wireHud()` subscribes `glassesHub.onTouch`, gathers data, pushes a 5-row `0x4E` text frame, refreshes every 30s while held up. `renderHud()` is **pure + unit-tested** (`server/src/__tests__/glasses-hud.test.ts`). **Layout** (`docs/g1-protocol.md` "Text layout behaviour"): row 1 = status bar `HH:MM Dow DD ·  …  NN%` (glasses battery right-aligned via a char target); rows 2-4 = **Mail / Chat / Agents**, each `M3 · <latest preview…>` (count + `·` dot divider + truncated latest item); row 5 spare. Data: battery = min(L,R); mail count `MailSync.getInboxUnreadCount` (30s cache) + latest subject `MailSync.getLatestSubject()` (set on each mail push); chat = unread non-muted rooms + newest room `sender: body` (`chatRoomsStore`); agents = sessions with `needsAttention` + newest snippet (the `@amar` excerpt). Head-up angle set on connect (default 30°, `0x0B`), runtime-adjustable via `setHeadUpAngle` RPC. **Phone battery** is in the snapshot (`PushService.glassesStateJson()` via `BatteryManager`) but the HUD no longer shows it. **Alignment caveat:** right-align uses an *approximate char-count* target (proportional font) kept a few chars short of flush so it never tips into a wrap (which would break the 5-row layout); a per-glyph metric pass could make it exact.
  - **Native teleprompter** (`0x09`, `docs/g1-protocol.md` §20): the glasses hold ONE 512-byte text buffer and never page it, so `server/src/glasses/teleprompter.ts` owns the script — `paginate()` (5 rows × ≤38 chars, ≤512 B) + `TeleprompterController` (page 1 = action 1 INIT, taps page with action 3 TEXT: right single-tap `0xF5 0x01` next, left prev; double-tap `0x00` = the glasses left the feature, session ends without a write; `isActive()` silences the HUD via `wireHud`'s `suppressed`). Routes `GET /glasses/teleprompt`, `POST /glasses/teleprompt/{start,next,prev,goto,exit}`; CLI `con glasses teleprompt <file|->|next|prev|goto|exit|status`. APK: `G1Protocol.encodeTeleprompterPage` / `parseTeleprompterAck` (status byte 9, no 0xC9), `BleManager.teleprompterShow/Exit` (L→R; exit = action 5 then `0x18`). Keep-alive is the existing 8 s heartbeat (`0x25 sub 4` IS the sync the UI task counts). **Not yet seen on the wire** — first live run checklist is in §20; `--multipart` is the fallback if a one-packet INIT does not open the app.
  - **Native countdown timer** (`0x07` = `PUT_COUNTDOWN_TIMER`, `docs/g1-protocol.md` §21): frame `[0x07, seconds u32 LE, enable]` — 6 bytes, NO length header (unlike 0x06/0x08/0x09/0x0A). `seconds` is a DURATION the firmware decrements itself (UI logs it as hh:mm:ss; the screen exits at 0). `enable=0` cancels. 99:59:59 is the cap (the lens formats `%02d` hours). `server/src/glasses/timer.ts` owns `parseDuration` (`10m`, `1h30m`, `1:30:00`, `ten minutes`, `an hour and a half`; bare number = minutes) for the route `POST /glasses/timer {duration|seconds}` + `/timer/cancel`, the CLI `con glasses timer <dur>|cancel`, and the ring verb `timer <dur>` / `timer cancel` (`ring-schema.md` `verbs.timer`, aliases `countdown`/`set`; a remainder that is not a duration falls through to the LLM — "set the mood" is never an error). APK: `G1Protocol.encodeCountdownTimer/encodeCountdownCancel`, `BleManager.countdownTimer` (L→R), RPC `countdownTimer {seconds, enable}`. **Not yet on the wire** — first `con glasses timer 1m` is the check (§21).
- **Arbitration**: notifications overlay everything (firmware-managed); HUD owns the screen while tilted up; the **SPA mirror re-asserts on head-down** (`mirror.ts` subscribes `onG1Event` → `pushNow()` if enabled) so a HUD/notification clobber doesn't leave a blank panel.
  - **Config**: `server/src/glasses/config.ts` (`glasses-config.json`, atomic write) — `{notifyEnabled, channels{}, hudEnabled, headUpAngleDeg}`. Routes `GET/POST /glasses/config`. CLI `con glasses hud on|off` + `con glasses config [--notify on|off] [--channel <src> on|off] [--angle 0-60]`. SPA toggles in `GlassesSettings.tsx`.
- GlassesService's ongoing notification updates with connection + battery (`GlassesState.addListener`); grouped with PushService's under `console.ongoing`.
- Mic → STT path: **touchbar long-press-right auto-arms the mic** (`server/src/glasses/touch-autowire.ts` subscribes `glassesHub.onTouch`; 0x17 → `setMic(true)`, 0x18 → `setMic(false)`). `POST /glasses/mic {active:true}` is the manual path. LC3 frames fan out over `WS /glasses/mic`. Decode to PCM is a consumer concern — see `docs/g1-mic-stt-recipe.md` for the three options (hub/APK/browser).
- **Offline audio buffering**: if the hub WS dies mid-utterance, `PushService.audioBuffer` (cap 3000 frames ≈ 60 s) holds LC3 frames and drains on reconnect. Touches/state not buffered (transient). Audio-only — drops from the front when full.
- **Reverse-engineering log**: the APK forwards every inbound BLE frame (classified by `BleManager.Listener.onFrame`, kinds: `audio|touch|heartbeat|ack|unhandled|battery|wear`) except audio (too noisy) and — unless verbose — heartbeats. Hub appends NDJSON to `~/.config/console/glasses-research.log` via `GlassesResearchLog` (rotates at 5K lines). Toggle with `con glasses research on|off`, tail with `con glasses research tail [N]`. Unknown opcodes get `unknown: true` for cheap jq filtering — still the path to filling remaining gaps in `docs/g1-protocol.md` §12.
- **Battery / wear / charging-case state** (source: the g1-reverse firmware decompile — PRIMARY — then MentraOS; `docs/g1-protocol.md` §12/§14/§17, `memory/project_g1_mentraos_reference.md`). Arm battery uses `0x2C 0x01` query / `0x2C 0x66 <pct>` reply, fired once on connect then every ~10 heartbeats (~80s) by `BleManager`. On-head detection is unsolicited `0x27 0x06` (worn) / `0x27 0x07` (removed). Charging-case state rides the same `0xF5` touchbar pipe: subcmd `0x0E` = `case-charging` (byte[2] 0/1), `0x0F` = `case-battery` (byte[2] 0..100), `0x06/0x07` = removed, `0x08` = opened, `0x0B` = closed. All three surface on `GlassesSnapshot` as `worn` / `caseBattery` / `caseCharging`.
